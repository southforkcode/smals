# Direct proof receipts

Sources: [B008](../plans/01_foundation_and_contracts.md#b008), [delivery evidence rules](../plans/00_delivery_and_evidence.md). Manifests under plans/verification/increments bind an increment to nonempty build targets, source globs and nonempty named cases. Each case declares argv, timeout, expected exit, required output and optional hashed output artifacts. Backend unavailable is an explicit nonpassing observation. The runner does not infer specification closure.

scripts/prove.py accepts --increment/--out and optional --root/--cmake/--seed/--work-timing. Source/tool/spec/manifest digests and git revision/tree identify inputs. It runs CMake's declared build targets, then exact case argv (substituting only root/build/python/seed tokens), capturing separate stdout/stderr files and a hashed command JSON record for every invocation. Output lives under ignored temp/, never source/test trees; a nonempty output directory is refused to prevent stale logs from passing. No shell is used for case execution. Commands have bounded timeouts; failed execution, timeout, missing output, missing log, empty selection and unavailable backend cannot pass. Artifact hashes are compared to independent manifest expectations when declared.

A receipt's passed field is a convenience summary, not authority; later audit replays evaluations from hashed command records, manifest and dependencies. Work timing is copied from agent-supplied attempt metadata with a separate command elapsed_seconds field. An in-progress attempt may have no end; no runtime clock overwrites the earlier work start. Bootstrap receipts are proof observations rather than a declaration that integration/cleanup/requirement closure is complete.

Tool tests use isolated temporary CMake targets and executable Python cases, independent expected stdout/exit/artifact bytes, and actual timeouts. Reruns use fresh output paths and compare stable input/artifact hashes rather than timestamps or build-output noise. Errors at filesystem/process boundaries become failed receipts and actionable diagnostics. Native profile dispatch is not yet implemented; unsupported backends remain unavailable.
