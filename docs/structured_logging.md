# Structured native logging and coverage

Sources: project contributors, CODE_STANDARDS.md and B015 in plans/01_foundation_and_contracts.md. Log records are one JSON object per line with level, unit, event and message. Shared entry/debug/info/warning/error emission escapes quotes, backslashes and control bytes while preserving valid UTF-8. A named status reports unknown levels and sink failure; the low-level writer does not recursively log its own failures. Unit names are internal nonempty identifiers, asserted in debug builds; release builds omit that sanity assertion.

CLI/diagnostic/trace callers use the shared API. Diagnostic messages retain their original code/phase/span/reason text inside the structured message, and originating errors are emitted once. Result/Diagnostic values and artifact prevention remain unchanged. Tests compare independent exact JSON, all levels, escaped controls, invalid severity and failed sinks.

Changed implementation units are instrumented with Clang source-based coverage in a separate Release build, preserving the normal build. LLVM profile merge/export supplies branch observations; tools/check_coverage.py reports missing/uncovered branches and fails if either outcome of a changed-unit branch has no execution. An intentionally incomplete run must fail before the complete cases pass. Debug and NDEBUG probes separately demonstrate the assertion's presence/absence. These are software/harness checks, not agent work timers. Windows is untested; use clang++ -fprofile-instr-generate -fcoverage-mapping, llvm-profdata merge and llvm-cov export with the same unit list when that host is available.
