# Receipt audit and requirement closure

Sources: [B009](../plans/01_foundation_and_contracts.md#b009) and [evidence/closure rules](../plans/00_delivery_and_evidence.md). Audit is read-only. It recomputes acceptance from the current bound manifest, exact input/spec/tool hashes, Git baseline/tree identity, hashed command JSON and raw streams. Convenience passed/errors fields never substitute for observations. Validate every command record against its receipt metadata, build target/argv/status, case IDs/argv/status/output/artifacts, and copied work timestamps. In-progress work may lack an end; completed work must have valid ordered UTC bounds and matching elapsed seconds. Never derive active/waiting work from elapsed time.

scripts/audit_evidence.py supports --increment ID --receipt DIR (or latest temp/evidence/ID/proof-*/receipt.json), and --requirement KEY --closure. Requirement manifests bind the exact normative table text/digest and an explicitly reviewed clause inventory, required scopes and positive/negative case links. Every linked receipt must audit, every referenced case must exist and its declared scope must support the obligation. Unreviewed/open inventories, missing clauses/evidence, unsupported scopes and stale dependencies reject closure; nothing is marked complete automatically. Native evidence is unavailable at this stage and cannot be inferred from host receipts. B012 will extend explicit evidence-scope policy.

Requirement audits also replay one linked discriminating case with its original argv/expected result and bounded timeout; replay artifacts/logs go to a fresh ignored temp directory. The inventory itself is not rewritten. The initial inventory seed is a separate increment. The audit boundary translates malformed external JSON/paths/process errors to diagnostic values.
