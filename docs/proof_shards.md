# Bounded proof selections

Sources: [B013](../plans/01_foundation_and_contracts.md#b013), [evidence scope policy](evidence_scopes.md), and delivery limits. Cases may carry one case_set name. --case-set selects that group (all/default selects all); --shard I/N selects manifest-order positions I-1, I-1+N, ... with 1 <= I <= N <= 64. Empty/unknown selections and declared case-timeout sums above the at-most-120-second proof budget fail before building. Selection metadata and actual IDs are recorded; a passed shard does not claim omitted cases.

The collector applies remaining time to subprocesses and rejects a receipt whose total measured proof runtime exceeds its budget. This is execution-harness timing, separate from copied agent development-work timing. Inputs/manifests remain fully hashed; the auditor independently reconstructs selection and validates cases and runtime bounds. Requirement links must name a case actually present in the referenced shard, not merely listed in the full manifest.

CTest mappings and increment labels live under plans/verification/native_cases.cmake rather than source/test code. Native domain cases and focused Python suites have per-case 120-second CTest timeouts; labels support narrow reruns. Demonstrate one small nonempty shard under 120 seconds and reject oversize/empty requests without silently skipping. Windows recipe: use the standard build, `ctest --test-dir build/smil -L B013 --output-on-failure`, then `uv run python scripts/prove.py --increment B013 --case-set smoke --shard 1/2 --out temp/evidence/B013/windows`; Windows remains untested here.
